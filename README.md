# News Consulting

Notionに登録された志望企業について、重要な公式発表と新卒採用情報を毎朝収集し、DraftsとGoogleスライドへ記録するプロジェクトです。

配信は日本時間の毎日8:00（土日祝を含む）に、同じCodexプロジェクト内の「毎日ブリーフィング」スレッドで実行します。ブリーフィング本文はチャットへ掲載せず、指定されたDraftsの同一ページの既存本文をいったんすべて消してから当日分を書き込みます。その検証後、Googleドライブ内の月次Googleスライドへ当日分を1枚追加します。

> [!IMPORTANT]
> このプロジェクトを運用・変更する際は、本READMEだけで判断せず、[詳細な運用仕様](OPERATION_SPEC.md)と[毎日配信用の指示書](DAILY_BRIEFING.md)も必ず確認してください。

> [!IMPORTANT]
> トリガーを受信するたびに、過去の確認結果に依存せず、必ず最初に最新の `README.md` を開いて全文を確認してください。その後に `OPERATION_SPEC.md` と `DAILY_BRIEFING.md` を確認し、日次タスクを開始します。

> [!IMPORTANT]
> 日次タスクの全工程について、利用者へ承認、許可、作成依頼を一切求めてはいけません。トリガー受信後は、調査、Draftsの消去・書き込み、Googleスライドの作成・追記・検証まで連続して自動実行します。

## タスクの開始条件

同じCodexプロジェクト内の「毎日ブリーフィング」スレッドで、次の指示が展開された場合に日次タスクを開始します。

> プロジェクト内のREADMEを確認し、情報発信を行なってください

トリガーを受信するたびに、必ず最初に最新の `README.md` を全文確認します。以前の実行時に確認済みであっても省略しません。続けて `OPERATION_SPEC.md`、`DAILY_BRIEFING.md` の順で最新内容を確認します。曜日による特別フローは設けず、毎日同じ構成で実行します。

## ブリーフィング内容

ブリーフィングは、次の2項目だけで構成します。ビジネスフレームワーク、GD、ケース面接問題、回答へのフィードバックは扱いません。

### 1. 直近1か月以内の重要な公式情報（3件）

- Notion「就活ワークスペース → 企業研究 → コンサル業界」に登録された企業のうち、`志望度` が `レベル3`、`レベル4`、`レベル5` の企業だけを対象とします。
- 配信日から遡って1か月以内に新規公開された情報から、重要度の高いものを必ず3件選びます。
- 企業公式のプレスリリース、ニュースルーム、IR情報、適時開示などの一次情報を参照します。
- 各項目は、企業名と発表内容が見出しだけで具体的に分かる表現にします。
- URLは情報ごとに対応させ、実際に出典ページを開いて公開日と本文を確認します。
- 同じ企業や同じ話題への過度な偏りを避けます。

### 2. 前日に新規公開された採用情報

- 同じNotion「コンサル業界」に登録されたすべての企業を対象とし、`志望度`による除外は行いません。
- 日本時間で配信日の前日0:00〜23:59に新規公開された新卒採用情報だけを掲載します。
- インターン、本選考、説明会、セミナー、採用イベント、応募期限などを対象とします。
- 企業公式サイト、公式採用ページ、公式SNSなどを参照します。
- 各項目は、企業名と募集・イベント内容が見出しだけで具体的に分かる表現にします。
- 開催日や応募期限が前日であるだけの情報を、前日に公開された情報として扱いません。
- 該当件数は制限せず、確認できたものをすべて掲載します。該当がなければ、その旨を明記します。

## Draftsへの共有

- ブリーフィング本文の共有先はDraftsです。
- 毎日新しい下書きを作成せず、次の同一Draftsページを毎日全文書き換えます。
  - 固定タイトル：`コンサル業界ブリーフィング`
  - 固定UUID：`2CCDE2F6-3B0E-45B1-8DCC-7C3D2E8C9AA6`
- ページは固定UUIDで取得し、タイトル検索だけで推測しません。
- 書き換え前後に対象ページのUUIDを確認します。既存本文をいったん空にし、その同じUUIDへ当日分の完成本文を書き込み、更新後に本文を読み戻して保存結果を検証します。追記方式にはしません。
- 先頭行は固定タイトル `コンサル業界ブリーフィング` とし、次に日付を記載して、「1. 直近1か月以内の重要な公式情報」「2. 前日に新規公開された採用情報」の見出しを付けます。
- 重要な公式情報と新卒採用情報の各見出しは、どちらもDraftsのタスク形式 `- [ ] 見出し` とし、未完了チェックボックスを付けます。公開時にチェック状態を変更しません。
- 各見出しの直下へ公式URLをそのまま記載します。既に有効化されたLink Modeを前提とし、日次タスクでLink Modeを再操作しません。
- Draftsには要約や注目点などの説明本文を記載しません。見出しだけでは分かりにくい固有名詞や専門用語を避けられない場合に限り、直下へ `※用語：簡潔な説明。` の形式で短い補足を付けます。通常エディタ内では部分的な文字サイズ変更を行いません。
- Draftsの操作はCLIまたはMCPだけで行い、Computer Useを使用しません。更新後に同じUUIDを読み戻し、各項目の `- [ ]` と公式URL文字列が消えていないことを確認します。

固定UUIDのページを取得できない場合や、読み戻したタイトルが固定タイトルと一致しない場合は、別の下書きを推測して作成・上書きせず、日次公開処理を保留して状況を報告します。

## Googleスライドへの記録

- Draftsの更新と同じ日次タスク内で、自動的にGoogleスライドも更新します。作成・追記・検証のいずれについても利用者の承認を求めません。
- 対象アカウントは `sekiaoi0818@keio.jp`、保存先はマイドライブ内「コンサル毎日ブリーフィング」フォルダに限定します。
- フォルダID：`13Jpr1sExTpXQWFNN-5vfSvj0Kb3MZBU0`
- ファイルは1か月につき1つとし、ファイル名は `YYYY年MM月` とします。
- 当月ファイルが存在しない場合は、指定フォルダ内の直近月ファイルをデザイン参照として当月ファイルを作成します。複製した過去月の内容は当月ファイル内で除去し、当日分だけを残します。存在する場合は末尾へ当日分のスライドを1枚追加します。
- スライドに掲載するのは、Draftsと同じ2項目の調査結果だけです。フレームワーク、GD、ケース面接関連の内容は掲載しません。
- 各情報は「具体的な見出し」「詳細（2文以内）」「公開日」「対応する公式URL」で構成します。Draftsより詳しくしますが、詳細は1件につき必ず2文以内に収めます。
- スライドのフォーマットは固定テンプレートを必須とせず、読みやすさを優先して決定します。
- すでに運用中の当月ファイルでは、既存スライドを上書き、削除、並べ替えず、更新後に末尾へ1枚増えたことを確認します。当月ファイルを直近月ファイルの複製から新規作成する場合に限り、複製先に残った過去月スライドを削除できます。
- 指定フォルダと、本プロジェクトがその中に作成したファイル以外は操作しません。

Draftsの固定ページを確認できない場合は、DraftsとGoogleスライドの同時更新を開始せず、利用者へ報告します。
